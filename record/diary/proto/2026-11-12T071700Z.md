**Decision: why the return's guess is a setting below its own range.** `return.afterSeasons` allows 0.25
at the least (about 7 days). The overlay sets the value directly, so the range is not applied to it, and
`proto.return.afterSeasons` has a range of its own (0.05 to 8). Why not widen the range in
`WalkersConfig.Director.cs`: that is feature 1's file, and the prototype does not need it.

**Decision: the checks.** `.github/workflows/build.yml` gets one step first that compares a PR with its
base: if every changed file is under `record/`, the build, the server test and the uploads are skipped
and the job passes. The job itself always runs, so the required check never waits. A push to `main` runs
in full every time. Why not `paths-ignore`: a skipped workflow leaves a required check pending (SETUP).

**Known rough edges** (in the PR too): `/walkers config` shows the prototype's value while it is on; a
reload while it is on lists the eleven values as changed; a true form already standing keeps its health
until it next shifts; a walker that died before the switch keeps its 1.1.1 return day; the settings file
gains a `proto` section on first load, and once `Walkers/Proto/` is removed that section is an unknown
key: a warning at each start, and the loader then adds no new settings to that file until it is deleted.
